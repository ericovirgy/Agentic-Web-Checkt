# 05 — Naming research: availability and conflicts

Date: 2026-10-04. Checks performed from the sandbox:

- **npm**: `npm view <name> version` (E404 = free). Any name is also publishable as a scoped package (`@<your-scope>/<name>`), so a taken unscoped name is a branding problem, not a hard blocker.
- **GitHub user/org**: GitHub user-search API (`<name> in:login`) plus a fetch of `https://github.com/<name>` (404 = free). The raw `api.github.com/users/<name>` endpoint is blocked by this session's proxy, so the page fetch is the authoritative signal.
- **GitHub repos**: repository search `<name> in:name`, sorted by stars; top hits listed.
- **Domains**: only a DNS A-record lookup (`getent hosts`) for `.com/.dev/.io`. "no-A" means no A record today, **not** that the domain is unregistered. Treat every domain column as UNVERIFIED unless it says RESOLVES (which means it is definitely taken).
- **Trademark/product**: quick web search only; not a USPTO/EUIPO search.

## Summary counts

- Fully clear on npm **and** GitHub user/org with no product conflict: `agentic-web-check`, `webagentcheck`, `web-agent-check`, `readyforagents` (4 of 19).
- Clear on npm/GitHub but blocked by trademark: `agentic-lighthouse`.
- Hard conflicts with a major incumbent: `agentscope` (Alibaba), `agentgrade` (direct competitor), `agent-lighthouse` (Google trademark + ForkPoint competitor), `agentproof`, `agentpass`, `agentlens`, `agentable`, `agentready`/`agent-ready`.

## Ranked top 3

1. **agentic-web-check** (CLI alias `awc`, npm `agentic-web-check`, optional scoped `@<scope>/agentic-web-check`).
   Free on npm and GitHub, no product or trademark collision, and it already matches the repository. "Agentic web" is the vocabulary Google Lighthouse, Vercel and ForkPoint use, so search intent lines up with the name. The only cost is length, which the `awc` binary alias absorbs. Domains unverified; `.com/.dev/.io` show no A record, so check a registrar before committing.

2. **web-agent-check / webagentcheck** (hyphenated for npm, concatenated for domain and GitHub org).
   Equally free and conflict-free, one word shorter and more pronounceable. Ranked below #1 only because "web agent check" can be parsed as "a check of web agents", which is the opposite of what the tool does; several top GitHub hits for `agentcheck` show that readers already make that mistake.

3. **readyforagents** (as the landing-page / domain brand, with #1 as the package name).
   Free everywhere we could check and reads as a clear user-facing promise ("Is your site ready for agents?"). It is awkward as a CLI or npm name (14 characters, no separators), so it works best as the marketing name layered over `agentic-web-check`. `readyforagents.com` resolves to something, so verify ownership before investing in it.

**Do not use**: `agentscope` (Alibaba's 32k-star framework), `agentgrade` (live competitor doing exactly this), `agent-lighthouse` / `agentic-lighthouse` (Google Lighthouse trademark plus its own "Agentic Browsing" audit), and `awc` as the public name.
