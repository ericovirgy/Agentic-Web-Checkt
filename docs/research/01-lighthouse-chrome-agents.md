## 1. Google Lighthouse — current state

- **FACT** Latest npm version is **13.5.0**, published 2026-09-18; `engines.node >=22.19`; deps include `puppeteer-core ^25.9.0`, `chrome-launcher ^1.2.1`, `axe-core ^4.13.0`. Source: https://registry.npmjs.org/lighthouse (dist-tags/time).
- **FACT** Five categories in `core/config/default-config.js`: `performance`, `accessibility`, `best-practices`, `seo`, **`agentic-browsing`**. Source: https://raw.githubusercontent.com/GoogleChrome/lighthouse/main/core/config/default-config.js
- **FACT** Timeline (changelog.md, https://raw.githubusercontent.com/GoogleChrome/lighthouse/main/changelog.md):
  - 13.2.0 (2026-04-30): "agentic: add new agentic browsing category"; llms.txt check; webmcp-form-coverage / webmcp-registered-tools / webmcp-schema-validity audits.
  - 13.3.0 (2026-05-07): "New agentic browsing category added to default config" (expected Chrome 150).
  - 13.4.0 (2026-06-09): llms-txt tweaks; "viewer: disable agentic-browsing in PSI api call".
  - 13.4.1 (2026-07-20): WebMCP gatherers check `document.modelContext`; "Enabled Agentic Browsing category via PSI API".
  - 13.5.0 (2026-09-17/18): "ard-schema: add Agent Resource Discovery audit"; llms.txt + ARD grouped under "agent discoverability".
- **FACT** The category definition (default-config.js):
  - title "Agentic Browsing"; description: "These checks ensure high-quality, browsable websites for AI agents and validate the correctness of WebMCP integrations. This category is still under development and subject to change."
  - `supportedModes: ['navigation', 'snapshot']`, `categoryScoreDisplayMode: 'fraction'` (no 0–100 score; shows passed/total).
  - auditRefs (all weight 1): `agent-accessibility-tree` (group agent-accessibility), `webmcp-form-coverage`, `webmcp-registered-tools`, `webmcp-schema-validity` (group webmcp), `cumulative-layout-shift` (CLS), `llms-txt`, `ard-schema` (group agent-discoverability).
  - Groups: "Agent Accessibility" ("best practices for improving the accessibility of the website for AI agents"), "WebMCP", "Agent Discoverability" ("discoverable resources, documentation, and catalogs for AI agents").
- **FACT** Audit internals (files under `core/audits/agentic/` and `core/audits/webmcp-*.js`, raw.githubusercontent.com/GoogleChrome/lighthouse/main/...):
  - `agent-accessibility-tree`: binary pass/fail; reuses the `Accessibility` (axe) artifact and fails if any of ~39 axe rules fail — e.g. `button-name`, `link-name`, `label`, `select-name`, `input-button-name`, `input-image-alt`, `document-title`, `aria-*` (allowed-attr, required-attr, roles, valid-attr-value, command-name, dialog-name, toggle-field-name, tooltip-name, treeitem-name…), `duplicate-id-aria`, `tabindex`, `autocomplete-valid`, `presentation-role-conflict`, `svg-img-alt`. Description links to developer.chrome.com/docs/lighthouse/agentic-browsing/accessibility-for-agents.
  - `llms-txt`: gatherer fetches `new URL('/llms.txt', finalDisplayedUrl)`; passes if Markdown has ≥1 H1, ≥1 Markdown link, ≥50 chars; 4xx ⇒ notApplicable; 5xx/fetch error/format failure ⇒ fail. Links llmstxt.org.
  - `ard-schema`: looks for `ai-catalog.json` via robots.txt `agentmap`, `<link rel="ai-catalog">`, HTTP `Link: rel=ai-catalog`, else `/.well-known/ai-catalog.json`; validates against the "Agentic Resource Discovery" spec (https://agenticresourcediscovery.org/spec/ — site blocked here, UNVERIFIED content); none found ⇒ notApplicable (score 1), warnings ⇒ 0.9, errors ⇒ 0.
  - `webmcp-form-coverage`: uses `Inputs` + `WebMCP` artifacts; a form "covered" if it has `webMcpToolname` or `webMcpTooldescription` (declarative `toolname`/`tooldescription` attributes); informative list of unannotated forms; notApplicable when WebMCP unsupported.
  - `webmcp-registered-tools`: informative; lists imperative + declarative tools (name, description, inputSchema, source/DOM node); warns above 40 tools.
  - `webmcp-schema-validity`: checks `WebMcpSchemaIssues` (missing toolname / tooldescription / parameter name / parameter description); 1 = clean, 0.5 = warnings only, 0 = errors.
  - WebMCP gatherer (`core/gather/gatherers/webmcp.js`): enables CDP domain `WebMCP`, listens to `WebMCP.toolsAdded/toolsRemoved`; `isSupported` requires the CDP domain AND `navigator.modelContext || document.modelContext` present. **INFERENCE**: WebMCP audits are only meaningful on Chrome builds with WebMCP (origin trial / flag); on other Chromes they report N/A, so a scanner wrapping Lighthouse gets no WebMCP signal unless it runs a recent Chrome with the feature on.
- **SECONDARY** Google docs state the category appeared in Chrome DevTools from M150 (stable ~2026-06-30), is deliberately unscored ("gather data and provide actionable signals"), and can be run with `npx lighthouse <url> --only-categories=agentic-browsing`. Sources (blocked here, summarized by search): https://developer.chrome.com/docs/lighthouse/agentic-browsing , https://developer.chrome.com/docs/lighthouse/agentic-browsing/scoring , https://developer.chrome.com/blog/agent-ready-toolkit . The `--only-categories=agentic-browsing` id itself is **FACT** (category id in default-config.js).
- **FACT** No audit in the repo checks things like robots/AI-crawler policy, canvas-only UI, cookie-wall blocking, iframe checkout, hover-only menus, infinite scroll, CAPTCHA, or structured data for agents (only the 7 audits above exist; `core/audits` listing https://github.com/GoogleChrome/lighthouse/tree/main/core/audits).
- **UNVERIFIED** Open issues/PRs discussing further agentic audits (GitHub issue search not reachable from this session; `gh api` returned 403).

## 2. Lighthouse architecture & embeddability

- **FACT** Node API: `core/index.js` exports `async function lighthouse(url, flags = {}, config, page)` (→ `navigation(page, url, {config, flags})`), plus `Audit`, `Gatherer`, `defaultConfig`, `desktopConfig`, `startFlow`, `generateReport` etc. Tarball `lighthouse-13.5.0/core/index.js`. Also typed entrypoint `lighthouse/types` (changelog 13.4.0).
- **FACT** Result object: `{lhr, report, artifacts}`; flags include `port`, `logLevel`, `output`, `onlyCategories`, `onlyAudits`, `skipAudits`. Source: https://raw.githubusercontent.com/GoogleChrome/lighthouse/main/docs/readme.md and readme CLI (`--port` "The port to use for the debugging protocol").
- **FACT** Custom gatherers/audits: config `{extends:'lighthouse:default', artifacts:[{id, gatherer:'./path'}], audits:['./path'], categories:{...}}`; arrays concatenate with defaults; `lighthouse --config-path=custom-config.js`. Source: https://raw.githubusercontent.com/GoogleChrome/lighthouse/main/docs/recipes/custom-audit/readme.md . Plugins (`lighthouse-plugin-*`, `--plugins`) can add audits+category but **cannot add gatherers**. Source: https://raw.githubusercontent.com/GoogleChrome/lighthouse/main/docs/plugins.md
- **FACT** Puppeteer integration: pass a Puppeteer `page` as 4th arg, or launch with chrome-launcher and `puppeteer.connect({browserWSEndpoint})`; docs warn to drop `--enable-automation` and set `defaultViewport: null`. Source: https://raw.githubusercontent.com/GoogleChrome/lighthouse/main/docs/puppeteer.md
- **FACT** Playwright: not mentioned in Lighthouse docs. Established pattern (playwright-lighthouse README, https://raw.githubusercontent.com/orieg/playwright-lighthouse/master/README.md): `chromium.launch({args:['--remote-debugging-port=9222']})` then `lighthouse(url, {port: 9222, ...})` — Lighthouse attaches over CDP to the Playwright-launched Chromium. **INFERENCE**: works because Lighthouse only needs a CDP endpoint (`flags.port`); caveat: Lighthouse's bundled `puppeteer-core` must be protocol-compatible with Playwright's Chromium build, and Lighthouse opens its own target/navigation (it does not audit the Playwright `page` object directly).
- **FACT** Weight: npm `unpackedSize` 19.2 MB for the package alone; a clean `npm install lighthouse@13.5.0 --ignore-scripts` produced **171 MB** in `node_modules`, 85 packages (largest: @sentry 47 MB, lighthouse 22 MB, @opentelemetry 22 MB, @paulirish/trace_engine 17 MB, chromium-bidi 10 MB, puppeteer-core 8.4 MB) — measured in this session. Chrome not included.
- **INFERENCE — wrap vs. build:**
  - Wrapping gives, for free: the official "Agentic Browsing" fraction, the axe-based `agent-accessibility-tree`, llms.txt/ARD/WebMCP checks, CLS, and credibility ("matches what Google reports"). Cost: +171 MB, Node ≥22.19, a full Lighthouse navigation (~10–30 s/page), Chrome-only, and its WebMCP audits are N/A on normal Chrome.
  - Independent Playwright checks can cover what Lighthouse does **not**: agent-perspective snapshots (`ariaSnapshot({mode:'ai'})` size/quality, unnamed refs), overlays blocking clicks, cookie/consent walls, cross-origin iframe checkouts, canvas/WebGL-only UI, hover-only nav, infinite scroll, bot-blocking (403/CAPTCHA to automation UA), robots/AI-crawler policy, structured data, cross-browser (WebKit/Firefox) behaviour, and multi-step flows.
  - Reasonable design: Playwright core + optional `lighthouse` adapter (dynamic `import('lighthouse')`, `onlyCategories:['agentic-browsing','accessibility']`, attach via `--remote-debugging-port`), surfacing Lighthouse's audit ids verbatim so results are comparable.

## 3. How agents see pages: Chrome DevTools MCP, Playwright MCP, Playwright API

- **FACT** chrome-devtools-mcp 1.10.1 (Node ^20.19||^22.12||>=23, Puppeteer-based; `--browserUrl`/`--autoConnect`, `--headless`, `--isolated`, `--slim`). `take_snapshot`: "Takes a text snapshot based on a11y tree listing page elements with unique identifiers (uid)" (params pageId, filePath, verbose); interaction tools take `uid`. Other tools: click/drag/fill/fill_form/hover/press_key/type_text/upload_file/click_at, navigate_page/new_page/list_pages/select_page/wait_for, emulate/resize_page, performance_start_trace/stop/analyze_insight, list_network_requests/get_network_request, evaluate_script, list_console_messages, get_css_styles, take_screenshot, screencast_*, lighthouse_audit, 14 heap-snapshot tools, extensions, PWA, 3p developer tools, WebMCP (list/execute). Source: https://raw.githubusercontent.com/ChromeDevTools/chrome-devtools-mcp/main/docs/tool-reference.md
- **FACT** @playwright/mcp 0.0.83 (2026-09-28) is a thin shim over `playwright` (deps `playwright 1.64.0-alpha-…`); tools: `browser_snapshot` (accessibility tree with `[ref=…]`), `browser_click/type/fill_form/select_option/hover/drag/press_key/file_upload/handle_dialog/wait_for/navigate/tabs/evaluate/console_messages/network_requests/take_screenshot/find`, opt-in `--caps=vision` (coordinate clicks `browser_mouse_click_xy`), `pdf`, `devtools`, `storage`, `testing`. Chromium/Firefox/WebKit/Edge. Source: https://github.com/microsoft/playwright-mcp . Since Playwright 1.62 the server is bundled: `npx playwright mcp` (release notes).
- **FACT** The bundled MCP captures the page with `page.ariaSnapshot({ mode: "ai", timeout: 5e3 })` (playwright 1.63.0 tarball `lib/index.js:671`). `_snapshotForAI` no longer exists in playwright-core 1.63.0 (grep of `lib/` returns nothing) — it was the private predecessor; **INFERENCE** treat `_snapshotForAI` as removed/replaced.
- **FACT** Playwright **1.63.0** (npm, 2026-09-04; node ≥20). `page.ariaSnapshot(options?)` and `locator.ariaSnapshot(options?)` → YAML string; options `mode: "ai"|"default"` (ai = adds `[ref=e2]` refs and includes `<iframe>` snapshots; since 1.59), `depth` (1.59), `boxes` (appends `[box=x,y,width,height]` viewport CSS px; 1.60), `timeout`, `signal`; `ariaSnapshotJSON()` same options returning JSON (1.63). `expect(locator).toMatchAriaSnapshot()` for assertions. Sources: playwright-core 1.63.0 `types/types.d.ts` (lines ~2101–2160, ~14517–14600); https://raw.githubusercontent.com/microsoft/playwright/main/docs/src/api/class-locator.md ; https://raw.githubusercontent.com/microsoft/playwright/main/docs/src/release-notes-js.md
- **FACT** Snapshot format: `- role "name" [attribute=value]` nodes, e.g. `- link "Home" [ref=e3]`; attributes checked/disabled/expanded/level/pressed/selected. Source: https://raw.githubusercontent.com/microsoft/playwright/main/docs/src/aria-snapshots.md
- **SECONDARY** Known pain points reported by users of Playwright-MCP-style snapshots: full-page snapshots of complex apps reach 50k–200k tokens; closed shadow DOM and canvas content are invisible; cross-origin iframes historically opaque (now included in `mode:'ai'` per types). Sources: qaskills.sh, dev.to (not primary).

**INFERENCE (cross-cutting):** DOM/a11y-tree agents (Playwright MCP, DevTools MCP, agent-browser, browser-use, Stagehand, Comet, Neon, Lighthouse's own model) fail on: controls without accessible names/roles, non-semantic click targets (`div onclick`), content in canvas/WebGL/SVG without text, closed shadow DOM, cross-origin iframes (payments), overlays/consent walls intercepting clicks, hover-only/`:focus`-less menus, lazy/infinite-scroll content outside the viewport, stale refs after DOM churn, and >10k-token trees (noise). Vision agents (computer use, Skyvern, Magnitude, Mariner-style) fail on tiny/low-contrast targets, custom scrollbars/dropdowns, ambiguous look-alike buttons, slow/animated UIs and are far costlier per step. Both classes fail on bot-detection/CAPTCHA, SSE/WebSocket pages that never go "network idle", and 2FA.

## Implications for an "agent readiness" scanner

1. **Google now owns the baseline.** Lighthouse ≥13.3 ships an official `agentic-browsing` category (7 audits, fraction score, "under development"). A scanner must at least reproduce or embed these ids (`agent-accessibility-tree`, `llms-txt`, `ard-schema`, `webmcp-*`, CLS) to be credible — and should clearly go beyond them, since Lighthouse checks none of the interaction-level failure modes above.
2. **Embed Lighthouse as an optional adapter, not the core.** It is ~171 MB installed, Node ≥22.19, Chrome-only, ~tens of seconds per page, and its WebMCP audits are N/A without an origin-trial Chrome. Attach via Playwright's `--remote-debugging-port` + `flags.port`; run `onlyCategories:['agentic-browsing']`.
3. **Make the agent's view the primary artifact.** Use Playwright 1.63 `page.ariaSnapshot({mode:'ai', boxes:true})` / `ariaSnapshotJSON()` — this is literally what Playwright MCP feeds LLMs — and score it: token size, ratio of interactive nodes with accessible names, unnamed `button`/`link`/`textbox`, generic `div` click handlers absent from the tree, duplicate names, depth.
4. **Test interaction, not just structure.** Simulate the common failure modes agents document: click interception by overlays/consent banners (agent-browser reports this explicitly), refs invalidated by DOM churn, hover-only menus, content outside viewport (browser-use's 1000 px threshold), cross-origin iframes for checkout, canvas-only UI, networkidle never settling (SSE/WebSocket).
5. **Check discoverability files the way Lighthouse does** (`/llms.txt` H1+link+≥50 chars; `ai-catalog.json` via robots `agentmap` / `<link rel=ai-catalog>` / `Link` header / `/.well-known/`), plus things it skips: robots.txt rules for AI agents, sitemap, structured data, HTTP status for automation user agents (bot blocking).
6. **Report WebMCP as "opportunity", not failure** — it's a CG draft in origin trial; detect `document.modelContext`/`navigator.modelContext` and `<form toolname>` attributes, and mirror Lighthouse's 40-tool warning.
7. **Cover both agent classes.** Provide a vision-side proxy too: screenshot-based checks for target size/contrast at 1280×720 (Anthropic's recommended baseline) and small-text legibility, since vision agents don't benefit from ARIA fixes.
8. **Run cross-browser.** Lighthouse and DevTools MCP are Chromium-only; Playwright gives WebKit/Firefox for free and some agents (Comet, Atlas, Neon) are Chromium forks with different feature sets — at minimum run the a11y snapshot in Chromium + WebKit.
9. **Keep output machine-readable and LLM-sized**: per-audit ids compatible with Lighthouse's LHR schema, plus a compact JSON/YAML of the trimmed a11y tree, so the scanner itself can be driven from MCP clients (as chrome-devtools-mcp's `lighthouse_audit` already is).
10. **Watch the moving targets**: Lighthouse's category text says "subject to change"; WebMCP API names moved (`navigator`→`document.modelContext`); Mariner was shut down; re-verify quarterly.
